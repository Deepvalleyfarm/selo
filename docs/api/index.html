SeloNachipa Open Network API

REST API v1.0.0 for platforms that list products on the SeloNachipa marketplace and send deliveries to the SeloNachipa rider network.

Base URLhttps://mabala-f2d65.web.app/api/v1
AuthOAuth 2.0 client credentials
FormatJSON · money in ngwee (K 1.00 = 100)
Machine-readableopenapi.json (OpenAPI 3.1)

Open Commerce. Publish your products with images, price and stock. They appear on the SeloNachipa marketplace for discovery and, if you choose, to other approved platforms. Each product carries a checkoutUrl: buyers tap Buy on your platform and pay on your own checkout. Your orders, payments and stock stay in your system.

Open Logistics. Quote, request and track deliveries carried by verified SeloNachipa riders, with a pickup PIN, a receiver delivery code by SMS and proof of delivery.

Who pays for delivery

The delivery fee is set by SeloNachipa. At checkout, call POST /delivery/quotes and charge your buyer exactly priceNgwee. You owe that amount to SeloNachipa in full. SeloNachipa splits it between the rider, the platform and the Social Fund as configured on SeloNachipa. Each delivery appears in GET /settlements as a DELIVERY_CHARGE; a cancellation before pickup adds a matching DELIVERY_REVERSAL.

Basics

Environments

Sandbox and production share the base URL. The client you sign in with decides the environment: sandbox client ids start sbx_, production ids start live_. Sandbox products are never shown to buyers. Sandbox deliveries never reach real riders: they move through every status automatically, one step a minute, and fire your webhooks. Request production access from the developer portal once your sandbox tests pass.

Access tokens

Exchange your client id and secret for a token at POST /oauth/token, then send Authorization: Bearer <token>. Tokens last 1 hour; fetch a new one when expires_in runs out or on a 401. Keep the client secret on your server, never in browser or mobile code. Secrets can be rotated or revoked at any time, and revocation takes effect on the next request.

A token carries only scopes that SeloNachipa granted and whose service (Commerce or Logistics) is enabled for your platform. Scopes are checked again on every call.

Idempotency

Every write (POST, PATCH, PUT, DELETE, except token and quote calls) needs an Idempotency-Key header. Repeating a request with the same key returns the first response. Reusing a key with a different body returns 409 idempotency_conflict. Deliveries are also unique per externalOrderRef, so sending the same order twice returns the existing delivery with "duplicate": true.

Rate limits

Each platform has a per-minute limit (120 by default, set by SeloNachipa). Over the limit you get 429 rate_limited with Retry-After: 60.

Integration flow

  1. Get a tokenPOST /oauth/token
  2. Publish productsPOST /products with a checkoutUrl; keep stock in sync with /stock
  3. Price delivery at checkoutPOST /delivery/quotes; add priceNgwee to the buyer's total
  4. Request the riderAfter payment, POST /deliveries with your order id as externalOrderRef
  5. Hand over the goodsGive the 4-digit pickupPin to whoever hands the parcel to the rider
  6. Follow progressdelivery.* webhooks or GET /deliveries/{id}

Delivery statuses

AWAITING_RIDER→RIDER_ASSIGNED→IN_TRANSIT→AWAITING_DELIVERY_CODE→COMPLETED

A delivery can end in DELIVERY_FAILED (the receiver couldn't be reached or refused) or CANCELLED (cancelled before pickup). The receiver gets a 5-digit delivery code by SMS; the rider enters it at the door, and that is the proof of delivery. While a job is active you see the rider's first name and number plate only.

Verify the signature

Every request carries webhook-id, webhook-timestamp and webhook-signature (Standard Webhooks). The signature is v1, followed by base64 HMAC-SHA256 of {id}.{timestamp}.{raw body}, keyed with the base64-decoded part of your whsec_ secret. Reject timestamps more than 5 minutes old, and use webhook-id to ignore repeats.

Node.js
import { createHmac, timingSafeEqual } from "node:crypto";

export function verify(secret, headers, rawBody) {
  const id = headers["webhook-id"], ts = Number(headers["webhook-timestamp"]);
  if (Math.abs(Date.now() / 1000 - ts) > 300) return false;
  const key = Buffer.from(secret.replace(/^whsec_/, ""), "base64");
  const want = Buffer.from("v1," + createHmac("sha256", key)
    .update(`${id}.${ts}.${rawBody}`).digest("base64"));
  return String(headers["webhook-signature"]).split(" ").some((s) => {
    const got = Buffer.from(s);
    return got.length === want.length && timingSafeEqual(got, want);
  });
}

Retries

Answer with any 2xx within 10 seconds. Otherwise SeloNachipa retries after 1 min, 5 min, 15 min, 1 h, 3 h, 6 h, 12 h and 24 h, then marks the event failed. You can list events with GET /webhooks/events and resend one with POST /webhooks/events/{id}/replay.

Errors

API errors return { "error": { "code", "message", "details" } }. The token endpoint uses OAuth's own shape, { "error", "error_description" }.

401invalid_client (token)Check the client id and secret.
